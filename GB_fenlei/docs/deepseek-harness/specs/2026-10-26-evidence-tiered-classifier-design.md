## 1. 背景与问题诊断

现有系统使用「字符 n-gram TF-IDF + 人工关键词特征 + 纯 Python softmax 回归」，参照表 105 条、7 个专业类。实测结论：

1. **交叉验证 100% 不可信**。关键词规则与训练标签同源，字符 n-gram 维度远大于样本量，模型在背题。无法据此判断泛化能力。
2. **置信度严重虚高**。待分类目录 179 组中 148 组（83%）置信度 ≥0.95；测试集 39 条中 28 条 ≥0.95。105 条样本不可能支撑这种把握。
3. **判定依据不可见**。API 返回的 `evidence` 前端未展示，用户无法判断结果是否可信。
4. **规则写死 7 类**。`KEYWORD_RULES` 直接绑定「金属材料」「试验检验」等固定专业名，上传专业名不同的参照表时规则失效。
5. **跨类冲突词**。`污染度`、`酸值`、`测试报告` 同时出现在两个类别，权重相同，互相抵消。
6. **中心词优先级缺失**。中文标准名称多为「中心词在后」：`X 试验方法` 应优先归试验类，`X 规范/技术要求` 通常是中性后缀。现有算法没有利用该结构。

已确认的验证基准：

- 用户提供的 `测试集.xlsx`（39 条，含标准号、标准名称、人工标注专业）。
- 其中 7 条与参照表冲突；用户逐条确认为**标错**，以参照表为准：第 22、24、32、36、37、38、39 行。
- 修正后，现有系统在该测试集上 39/39 = 100%（其中 23 条仅靠模型），说明该测试集偏简单，只能作为**回归基线**，不能作为泛化能力的唯一证据。
- 测试集标注混用专业名与系统名（如「航空金属材料技术」与「金属材料」），评估时统一按 `DEFAULT_SYSTEM_MAP` 映射为专业名。

## 2. 目标与验收标准

### 2.1 目标

1. 分类结果**可解释**：每条结果能列出命中的关键词、规则或相似标准。
2. 置信度**诚实**：上限 0.95，证据不足自动标「待复核」，不再出现大面积 0.99。
3. 准确率**不下降**：外部 39 条回归集保持 39/39；留一法给出真实泛化指标。
4. **类别动态**：仍由上传参照表决定，规则通过「概念 → 类别」映射适配不同的专业名称。
5. 保持 Win7 离线部署：Python 3.8、纯标准库、无新增依赖。

### 2.2 验收标准

| 指标 | 目标 |
|---|---|
| 外部回归集（39 条，修正后标注） | 39/39 = 100%，不得出现新的错误 |
| 留一法名称模式准确率（不使用标准号，含参照表号主体命中） | ≥85%，并公开报告；同时单列纯规则/kNN 准确率 |
| 高置信度区间（≥0.85）实际准确率 | ≥90% |
| 中置信度区间（0.70–0.85）实际准确率 | ≥75% |
| 置信度上限 | ≤0.95 |
| 低置信度（<0.70）自动标记 | 100% 标记为待复核 |
| 每条自动结果的可解释依据 | 至少 1 条（参照表/规则/相似/模型） |
| 现有前后端流程 | 四步流程不改变，旧 API 字段保留 |
| 现有测试 | 更新语义变化后的断言，全部通过 |

## 3. 总体架构

新增两个模块，改造既有模块：

```text
backend/
├─ rules.py       新增：概念种子、概念→类别映射、规则评分、例外规则
├─ mining.py      新增：从参照表挖掘高纯度特征词、依据词表
├─ classifier.py  改造：四级证据链、置信度模型、留一评估、结构化证据
├─ config.py      改造：概念种子、阈值；移除写死类别的 KEYWORD_RULES
├─ text.py        改造：分段、词条提取、字符 n-gram
├─ analysis.py    扩展：参照表体检返回依据词表
├─ export.py      改造：导出追加「判定依据」列
└─ main.py        扩展：返回新增字段（只增不减）
```

### 3.1 判定流程

```text
标准名称 + 标准号
      │
      ├─① 参照表精确命中 ──────────────→ 采用，置信度 0.88~0.95
      │    · 标准号完全命中
      │    · 标准名称完全命中
      │    · 标准号主体（去末尾年份）命中
      │
      ├─② 强规则 + 挖掘词计分 ─────────→ Top1 胜出
      │    · 人工概念种子（按类别动态映射）
      │    · 参照表自动挖掘的高纯度词
      │    · 中心词位置加成、最长匹配、例外规则
      │
      ├─③ 相似名称投票 ────────────────→ 最像的 5 条已分类标准
      │    · 字符 2~3 元组 TF-IDF 余弦
      │
      └─④ 模型兜底 ────────────────────→ 现有 softmax
           · 仅在②③都无有效证据时使用
           · 置信度强制 ≤0.60，自动待复核
```

**决策原则**：① 命中即采用；② 有有效证据即采用；② 无证据时用 ③；③ 也无证据时才用 ④。不会出现「模型覆盖强规则」的情况。

### 3.2 证据等级与置信度

| 等级 | `evidence_level` | 置信度范围 | 说明 |
|---|---|---|---|
| 参照表 | `reference` | 0.88–0.95 | 标准号/名称/号主体命中 |
| 强规则 | `rule` | ≤0.92 | 人工种子或挖掘词计分 |
| 相似名称 | `similar` | ≤0.85 | kNN 投票 |
| 模型 | `model` | ≤0.60 | 兜底，必标待复核 |
| 人工 | `manual` | 0 | 歧义组留空 |

## 4. 规则层设计（`rules.py`，历史模式，已移除）

### 4.1 概念与类别解耦

规则不再直接写「金属材料」等类别名，而是定义领域概念（concept），启动时把概念映射到参照表里实际存在的专业名。

```python
CONCEPTS = {
    "TEST":      {"label": "试验检验", "seeds": [...], "patterns": [...]},
    "FASTENER":  {"label": "紧固与连接件", "seeds": [...], "patterns": [...]},
    "MATERIAL":  {"label": "金属材料", "seeds": [...], "patterns": [...]},
    "LUBRICANT": {"label": "润滑油", "seeds": [...], "patterns": [...]},
    "COATING":   {"label": "表面处理", "seeds": [...], "patterns": [...]},
    "ASSEMBLY":  {"label": "结构装配", "seeds": [...], "patterns": [...]},
    "DESIGN":    {"label": "设计与工程通用规范", "seeds": [...], "patterns": [...]},
}
```

每个概念包含：

- `seeds`：`[(词, 权重)]`，人工领域词。权重 2–10。
- `patterns`：中心词/后缀模式，如 `试验方法`、`测定法`、`试验`。
- `neutral_suffixes`：不应单独决定类别的通用后缀，如 `规范`、`技术要求`、`通用要求`、`第X部分`、`方法`、`航空`、`飞机`、`用`。

**概念 → 类别映射算法**：

1. 对每个参照表类别（专业名），收集其下所有标准名称。
2. 对每个概念，计算该类别名称中命中 `seeds` 的加权命中率：
   `score(concept, category) = Σ 命中权重 / 类别名称条数`
3. 同时检查类别名本身是否包含概念种子（如「金属材料」包含「金属材料」）。
4. 取全局贪心分配：按 `score` 从高到低，把概念分配给尚未占用的类别。
5. 映射成立条件：`score ≥ 0.5` 且 `score ≥ 1.5 × 次优概念分数`。
6. 未映射的概念规则禁用；未映射的类别只依赖挖掘词、kNN、模型。

这样在标准 7 类表上映射稳定；换成「航空金属材料技术」等系统名或重新命名的专业名时，仍能通过种子词对齐。

### 4.2 评分

对一条标准名称：

1. 规范化（全半角、去标点、小写）。
2. 按空格和标点切分为子句（clause）。
3. 对每个类别累加命中规则：

```text
score[category] += weight × position_factor × source_factor
```

- `position_factor`：命中位置在名称后 1/3（中心词区）时 ×1.5，否则 ×1.0。
- `source_factor`：人工种子 1.0，挖掘词 0.8。
- **最长匹配优先**：仅当更长命中词与短词**同专业**，且更长词的**有效权重（weight × position_factor）不低于短词**时，短词才不计分（如「自锁螺母」覆盖「螺母」）。低权重挖掘长词不得删除高权重人工种子。
- 中性后缀不计分。

### 4.3 中心词与例外规则

1. **试验方法优先**：分两阶段扫描全部子句。第一阶段寻找以 `试验方法` / `测定法` / `检测方法` 结尾的完整中心词；只有第一阶段没有命中时，第二阶段才退化到以 `试验` / `检测` 结尾的半中心词（加成 ×0.75）。
   - 例外：仅当连接词 `及` / `和` / `与` **紧邻中心词之前**，且连接词前缀以 `要求/规范/规定/条件/性能/指标/规则/验收` 结尾时（如 `技术要求及试验方法`），才视为次要子句、不触发加成。`闪点与燃点测定法`、`钛及钛合金试验方法` 不属于次要子句。
2. **产品名词优先于通用后缀**：`螺母/螺栓/螺钉/垫圈/销/键/挡圈` 等命中的类别，不受 `通用规范/技术要求` 影响。
3. **覆盖层 vs 试验**：名称同时含 `覆盖层` 与 `评级` 时，COATING 加成，避免被 `试验` 抢走。
   - 试验中心词加成与覆盖层例外加成均生成合成命中记录并写入证据，保证证据有效权重之和等于类别分数。
4. **焊料/钎料归结构装配**：`焊料/钎料/钎剂` 命中 ASSEMBLY 时，优先于 MATERIAL 的单字金属词。
5. **单字金属词弱化**：`钢/铝/铜/钛/镁/镍` 权重 2–3，必须与 `板/带/管/棒/丝/型材/合金/化学成分` 等形态词或双字合金词组合才足以胜出。

### 4.4 种子词表原则

- 只保留**领域判别性强**的词；`规范`、`要求`、`航空`、`飞机`、`通用` 不进种子。
- 同一词不得出现在两个概念中；如确实跨领域，必须在例外规则中说明优先级。
- 种子词按概念分组，权重 2–10；具体产品名词 7–10，形态/属性词 2–5。
- 种子词表将作为 `config.py` 的一等数据，附注释说明每个词的判别理由。

## 5. 词条挖掘（`mining.py`）

### 5.1 候选词

对每个参照表名称：

- 按空格/标点切分为子句。
- 在每个中文子句内提取长度 2–6 的所有子串。
- 同时保留英文/数字 token（长度 ≥2）。

### 5.2 评分与过滤

对类别 `c` 的候选词 `t`：

```text
df_c   = 类别 c 中包含 t 的名称数
df_o   = 其他类别中包含 t 的名称数
purity = df_c / (df_c + df_o)
weight = purity² × log(1 + df_c) × (1 + 0.18 × (len(t) - 2))
```

保留条件：

- `df_c ≥ 2` 且 `purity ≥ 0.80`；或
- `df_c = 1` 且 `purity = 1.0` 且 `len(t) ≥ 5`（足够长的专有词）。
- 每个类别最多保留 80 个词，按权重降序。

**去冗余**：若短词 `t1` 被同类别更长词 `t2` 包含，且 `df_c(t2) ≥ df_c(t1)`，则丢弃 `t1`（保留更具体的词用于解释）。

### 5.3 依据词表输出

```json
{
  "profession": "表面处理",
  "system": "表面工程与防护技术",
  "keywords": [
    {
      "term": "阳极氧化",
      "support": 2,
      "purity": 1.0,
      "weight": 3.2,
      "source": "mined",
      "examples": ["铝及铝合金阳极氧化膜与有机聚合物膜 第1部分：阳极氧化膜"]
    }
  ],
  "top_examples": ["..."]
}
```

该报告同时用于：

- 前端「分类依据词表」页面；
- 每条预测的 `evidence` 文本。

## 6. 相似名称（kNN）

### 6.1 表示

- 对参照表每个名称构建字符 2 元组、3 元组集合。
- 计算 TF-IDF 权重（IDF 基于参照表名称集合，平滑）。

### 6.2 检索

- 对查询名称计算与每条参照名称的余弦相似度。
- 取 Top 5，过滤相似度 <0.20。
- 按相似度加权投票到类别。

### 6.3 使用方式

- 作为②的补充证据：`score[category] += 0.5 × 归一化相似度票数`。
- 当②的最高分 < `MIN_RULE_SCORE`（默认 4.0）时，作为主判据。
- 证据文本：`相似标准：<名称>（相似度 0.83，分类 X）`。

## 7. 模型兜底

- 保留现有 `SoftmaxRegression`；`FeatureExtractor` 改为**纯字符 n-gram**，移除关键词特征，避免与规则层重复计权，也避免规则变更后模型特征漂移。
- `NAME_PATTERNS` 已移除，兜底模型不再包含任何名称模式特征，只使用字符 n-gram。
- 训练流程与稀疏权重实现保持不变。
- 仅在②③均无有效证据时调用。
- 输出置信度 `min(0.60, 模型概率)`，`evidence_level = "model"`，强制 `needs_review = true`。
- 模型不再参与②的评分，避免与规则重复计权。

## 8. 置信度模型与校准

### 8.1 规则置信度

```text
top    = 最高类别得分
second = 次高类别得分（无则 0）
dominance = top / (top + second)          # 0.5 ~ 1.0
coverage  = min(1.0, top / 8.0)           # 证据绝对强度
raw = 0.55 + 0.40 × (2 × dominance - 1) × (0.6 + 0.4 × coverage)
raw = min(0.92, raw)                      # 强规则上限 0.92
```

- `dominance = 1.0`、`coverage = 1.0` → 0.92（强规则上限）。
- `dominance = 0.5` → 0.55。
- `top < 4.0` 时 `raw × 0.8`。
- 冲突（`dominance < 0.55`）时额外扣 0.05，并标记 `needs_review`。

### 8.2 其他等级

| 等级 | 置信度 |
|---|---|
| 标准号完全命中（一致率 100%） | 0.95 |
| 标准号完全命中（多数票 <100%） | 0.90 + 0.03 × 一致率 |
| 名称完全命中 | 0.93 |
| 标准号主体命中 | 0.85 + 0.05 × 一致率，上限 0.90 |
| kNN 主判 | 0.55 + 0.35 × 票数占比 × 平均相似度，上限 0.85 |
| 模型 | min(0.60, 概率) |

### 8.3 校准

- 用留一法收集 `(原始置信度, 是否正确)`。
- 按区间统计实际准确率：`[0.50,0.60)`, `[0.60,0.70)`, `[0.70,0.80)`, `[0.80,0.85)`, `[0.85,0.90)`, `[0.90,0.95]`。
- 若某区间实际准确率 < 名义值 − 0.10，该区间置信度上限下调到「实际准确率 + 0.05」。
- 校准表写入评估报告，预测时按区间映射，保持单调。
- 区间样本 <5 条时不做调整，避免小样本噪声。

### 8.4 待复核

- `REVIEW_THRESHOLD = 0.70`。
- 满足任一条即 `needs_review = true`：
  - `confidence < 0.70`；
  - `evidence_level == "model"`；
  - 规则冲突（dominance < 0.55）；
  - 无任何有效证据。
- API 同时保留 `low_confidence` 字段（与 `needs_review` 同义），兼容前端。

## 17. 纯数据驱动引擎（2026-10-26 重构）

- 状态：已完成（2026-10-26，纯数据驱动）
- 结论：概念模式（第 4 节 `CONCEPTS` + `rules.py`）整体移除，改为纯统计信号。系统不再依赖写死的专业类别、领域种子词或人工例外规则，所有类别与判定依据都来自上传的参照表。

### 17.1 三路统计信号

| 信号 | `evidence_level` | 说明 |
|---|---|---|
| 统计关键词 log-odds | `term` | 从参照表统计特征词在各专业中的对数几率，按命中强度累计类别分数 |
| 相似名称 kNN | `knn` / `similar` | 字符 2~3 元组 TF-IDF 余弦，取 Top-K 近邻并按相似度投票 |
| 字符 n-gram 贝叶斯 | `nb` | 字符 n-gram 朴素贝叶斯输出类别概率 |

参照表精确命中仍为最高优先级（`reference`）；三路信号加权合并后为 `ensemble`；人工为 `manual`。旧 `rule` 等级仅保留在类型定义中做兼容，统计引擎不再产生。

### 17.2 分层 5 折 out-of-fold 权重搜索

- 在**当前上传的参照表**上做**分层 5 折**：每折用其余折重建挖掘词表、相似名称索引和贝叶斯模型，只对留出折计算三路信号，因此每条样本恰好贡献一次 out-of-fold 信号。类别样本不足时自动降低折数（至少 2 折）。
- 在权重网格（默认 `0.0/0.25/0.5/0.75/1.0`）上搜索 `(term, knn, nb)` 组合：
  1. 跳过总权重为 0 的组合；
  2. **归一化到总和 1 之后**，每路信号权重必须 ≥ `ENSEMBLE_MIN_WEIGHT`（默认 **0.10**），否则丢弃；
  3. 每个候选用 `evaluate_ensemble` 评估，依次按**宏平均 F1 最高 → 准确率最高 → 最小权重最大 → 归一化权重字典序最小**排序。
- 最终权重随 `ClassifyResponse.ensemble_weights` 返回，前端在结果详情中展示；`evaluation.weights`、`tuning_accuracy`、`folds`、`method` 一并返回。
- 权重不是全局常量：换一份参照表会重新搜索，因此不携带任何领域先验。
- **为什么必须设最小权重**：只按准确率排序时，调参会把字符统计（nb）权重压到 0，权重变成 `term 0.5 / knn 0.5 / nb 0.0`；此时外部回归集从 38/39 掉到 32/39（“技术制图”等缺少词条与相似名称证据的名称只能落到均匀分布）。宏平均 F1 优先 + 10% 最小权重恢复了 38/39。

### 17.3 类别样本量提示

- `keyword_report` 的每组新增 `class_support`，表示该专业可用于统计的样本数。
- 样本数低于 10 时，该组返回 `warning`；参照表页在「分类分布」面板显示「以下类别样本量偏低，统计结果不稳定」横幅。
- 低支持类别的预测置信度相应降低，更容易进入「待复核」。

### 17.4 API 与前端变更

- `ReferenceAnalysis` / `ClassifyResponse` 移除 `concept_mapping`。
- `KeywordItem` 新增 `log_odds`，`source` 取值改为 `"statistical"`；`KeywordReport` 新增 `class_support` 与 `warning`。
- `ClassifyResponse` 新增可选 `ensemble_weights`（三路权重）与 `class_support`（各类样本数）。
- `EvaluationReport` 新增可选 `class_support`、`warnings`、`weights`、`tuning_accuracy`、`folds`，并沿用 `method`（固定 `stratified-5-fold`）、`name_mode`、`sample_count`。
- 结果页证据等级改为：参照表 `reference`、统计集成 `ensemble`、关键词统计 `term`、相似名称 `similar`、字符统计 `nb`、模型兜底 `model`、人工 `manual`。
- 参照表页词表弹窗新增「类别样本」列，来源展示「统计」；旧 `curated` / `mined` 仍可展示以兼容历史数据。

### 17.5 诚实基线（2026-10-26 最终指标）

现有参照表 105 行、**103 个唯一名称**，7 个专业类。分层 5 折 out-of-fold 指标：

| 指标 | 数值 |
|---|---|
| 5 折准确率 | **67.96%** |
| 5 折宏平均 F1 | **63.67%** |
| 权重 | `{term: 0.4286, knn: 0.4286, nb: 0.1429}` |
