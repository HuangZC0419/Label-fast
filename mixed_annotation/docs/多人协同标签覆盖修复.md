# 多人协同下实体标签被覆盖丢失的修复方案

> 适用模块：混合标注（`mixed_annotation` + `frontend/src/modules/mixed-annotation`）
> 关联项目：`国标3`（主诉）、`国标v2`（同源问题）
> 版本：2026-11-24

## 1. 现象

三个标注员同时使用同一个混合标注项目（`国标3`）时：

1. 顶部/左侧的「实体标签」列表显示不全——后加入的标签把别人的标签「顶掉」；
2. 标签从项目字典里消失后，正文中已经标注好的实体变成灰色（`#9A9DA3` / `lf-label-unknown`），并且界面上看不到它原本的标签名；
3. 标注本身没有丢，但失去标签归属，无法按标签导出与统计。

## 2. 根因

### 2.1 项目字典被整体覆盖写回（主因）

- `GET /api/projects/{id}` 返回项目字典快照；
- `ProjectDictionaryCard` 在页面打开时把 `project.labels` 复制成本地草稿；
- 用户每次增删标签，前端 `PATCH /api/projects/{id}` **提交整份 labels 数组**；
- 后端 `update_project()` 直接 `project[field] = changes[field]`，**整体替换**，没有版本校验、没有合并。

三人各自持有旧快照时，后保存者必然把先保存者新增的标签全部抹掉（last-write-wins）。
`国标3` 的 `project.json` 历史可以复现这一过程：

| 时间（UTC） | labels |
| --- | --- |
| 2026-11-10T07:47 | 关键工艺参数、适用范围、防护措施温度、电击电压（4 个） |
| 2026-11-10T08:10 | 上述 4 个 + 内外表面（5 个） |
| 2026-11-11T08:13 | 完全不同的 17 个标签（当前值），上述 5 个全部消失 |

### 2.2 未知标签缺少兜底展示（放大后果）

- `labelColor()` 对字典外的标签返回灰色 `#9A9DA3`；
- `syncHighlights()` 把字典外的标签统一注册成 `lf-label-unknown` 灰色高亮；
- 实体选中栏只显示实体文本，不显示标签名；
- 因此「标签丢失」在界面上表现为「标注内容变灰、没有标签」，且没有任何恢复入口。

### 2.3 标签列表被容器裁切（加重「显示不全」的观感）

`ProjectDictionaryCard` 的 `.dict-chip-row` 固定 `max-height: 112px; overflow-y: auto`，
标签超过约 3 行后只在内部滚动，用户看不到全部标签。

### 2.4 数据现状（修复前实测）

| 项目 | 字典标签数 | 被标注引用但字典缺失的标签 | 受影响实体数 |
| --- | --- | --- | --- |
| 国标3 | 17 | 关键工艺参数(9)、实验步骤(7)、适用范围(6)、机械性能(3)、防护措施温度(2)、内外表面(2)、电击电压(1) | 30 / 174 |
| 国标v2 | 14 | 安全要求(67)、试验条件(59)、试验方法(44)、术语与定义(35)、试验 器具(35)、试验步骤(26)、检验规则(21)、试剂选取(16)、设计要求(16) 等 21 个 | 约 330 |

标注偏移与正文完全一致（漂移 0），说明**标注数据本身完好，只缺字典项**。

## 3. 修复方案

### 3.1 后端：字典只做增量合并，永不隐式删除

`PATCH /api/projects/{project_id}` 请求体扩展为：

```json
{
  "name": "可选",
  "labels": ["兼容旧客户端的追加项"],
  "labels_add": ["新增标签"],
  "labels_remove": ["要删除的标签"],
  "relation_types": ["兼容旧客户端的追加项"],
  "relation_types_add": ["新增关系"],
  "relation_types_remove": ["要删除的关系"],
  "force": false
}
```

语义（服务端单次加锁内完成）：

1. `labels` / `relation_types` 仍接受，但**只作为追加**（union），旧前端不可能再删掉别人的标签；
2. 真正删除必须走 `labels_remove` / `relation_types_remove`；
3. 删除仍被标注引用的实体标签时，若 `force` 为 false，返回 **409**，文案包含每个标签的引用条数；`force: true` 才允许；
4. 合并结果写回 `project.json` 与 `projects.json`，返回完整项目对象。

新增只读接口：

```
GET /api/projects/{project_id}/labels/usage
→ { "used": { "标签名": 引用条数 }, "missing": ["被引用但字典缺失的标签名"] }
```

新增恢复接口：

```
POST /api/projects/{project_id}/labels/restore
→ { ...project, "restored": ["本次补回的标签"] }
```

`missing` 与 `restored` 的排序：引用条数降序，其次按标签名；去重、去空白。

### 3.2 前端：只提交增量 + 缺失标签可见可恢复

1. `ProjectDictionaryCard` 增删标签时改发 `{ labels_add: [x] }` / `{ labels_remove: [x] }`；
2. 删除仍被引用的标签时先弹确认，确认后带 `force: true` 重试；409 文案直接展示；
3. 卡片新增「字典缺失」区：列出 `missing` 标签（灰色虚线 chip，标注引用条数），提供「全部恢复」按钮；
4. `MarkdownAnnotator`：
   - 选中实体时显示标签名：`实体「文本」· 标签「xxx」`；
   - 标签不在字典时追加提示 `（字典缺失，可在左侧恢复）`；
   - 顶部统计新增 `N 处缺失标签` 的警示徽标；
5. `.dict-chip-row` 改为「折叠 3 行 + 展开全部」的切换，不再用固定高度藏标签。

### 3.3 数据恢复

在不删除任何现有标签的前提下，把「被标注引用但字典缺失」的标签补回字典：

- `国标3`：先补回历史版本中出现过的 5 个标签，再补回仅被标注引用的 实验步骤、机械性能；
- `国标v2`：按引用条数降序补回 21 个缺失标签；
- 写入前后校验：`labels` 只增不减；全部 `annotations.json` 哈希不变；`missing` 清空。

## 4. 验收

1. 后端：新单测覆盖「旧客户端全量提交不会删标签」「删除在用标签 409 / force 成功」「usage 统计」「restore 补齐」；
2. 现有 `mixed_annotation/backend/tests` 全绿；
3. 数据：`国标3`、`国标v2` 的 `missing` 均为空，标注字段与备份逐字节一致；
4. 前端：`npm run typecheck` 通过；页面可见全部标签、缺失标签区与恢复按钮；
5. 手工并发验证：两个客户端先后各加一个不同标签，两次刷新后两个标签都在。

## 5. 已知边界

- 两个标注员**同时编辑同一份文档**时，标注记录仍是整份覆盖保存（本次未改动），建议按文件分工；
- 字典的实时同步依赖打开项目/保存字典时的刷新，不做秒级推送。
