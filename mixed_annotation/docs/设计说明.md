# 数据标注与分类工具 混合标注 — 独立软件设计说明

- 日期：2026-11-04

- 状态：实施中

- 与主平台完全独立；主平台代码不做修改。

## 1. 目标

把扫描 PDF / 图片转换为可编辑的 Markdown，并让用户在**渲染后的 Markdown**上标注：

1. 字符级实体与实体关系；
2. 框选一个或多个自然段，整个选区作为一个标注打标签（如“铆接要求”）；
3. 图片 / 表格（在 PDF 预览中拖框截图，保存 PNG、页码、bbox、标题与备注）。

最终导出两类数据：兼容旧知识库的 `annotations.jsonl`，以及供知识图谱使用的 `graph.jsonl + assets/`。

不包含：模型训练、规则标注、NER、自动实体识别；本轮不做知识库侧的图片/表格展示 UI。

## 2. 总体架构

```
Vue 3 前端 (Ink & Signal 风格)
        │ /api
        ▼
FastAPI 主应用 (端口 3200) ──HTTP──► FastAPI OCR Worker (端口 8870)
        │                                  │
        │ 项目/文件/Markdown/标注/导出        ├─ HTTP ─► mineru-api (18000, 常驻)
        ▼                                  │            └─ MinerU GPU (CFwin11 / CUDA)
backend/data/                              └─ MinerU GPU 子进程 (回退)
                                           │
                                           ▼
                                     ocr_worker/data/
```

- 主应用不安装 MinerU；OCR 依赖隔离在 Worker 中。
- **唯一运行环境为命名 conda 环境 CFwin11（Python 3.12）**：API、Worker、主
  后端都用 `E:\Anaconda\envs\CFwin11\python.exe` 显式启动，不再使用 `CF`、
  `MinerUv2` 或外部 MinerU 工程。MinerU 默认通过常驻 `mineru-api` 调用，模型
  只加载一次；API 不可用时回退同一环境内的 MinerU 子进程。
- **PaddleOCR 回退已禁用，MinerU 是唯一 OCR 引擎**：项目位于中文路径时
  Paddle C++ 无法读取模型/图片路径。`OCR_ENGINE=auto` 与 `mineru` 都走
  MinerU；显式 `paddle` 会抛出明确错误。
- Worker 默认 3 并发处理任务（`OCR_WORKER_CONCURRENCY`，API 可用时自动为 3，
  子进程模式为 1），主应用轮询状态并下载结果 ZIP。
- 开发环境：默认从 Vite 5174 / 主应用 3200 / Worker 8870 / MinerU API 18000
  起自动选择空闲端口；Vite 代理目标由 `BACKEND_PORT` 跟随主后端。
- 当前部署：本机运行 `start.bat`，主应用可托管 `frontend/dist`；Worker 与
  MinerU API 仅监听本机回环地址或局域网，按需访问。旧 Docker 容器方案见

## 3. OCR

### 3.1 引擎与传输选择

- **MinerU 常驻 API（默认）**：`ocr_worker/mineru_engine.py` 通过 HTTP 调用
  `mineru-api`（默认 `http://127.0.0.1:18000`）：`POST /tasks` 提交 multipart
  文件与解析参数，轮询 `GET /tasks/{id}`，完成后下载
  `GET /tasks/{id}/result` 的 ZIP，安全解压并归一化。模型只在 API 启动时加载
  一次，Worker 可多任务并发。
- **MinerU GPU 子进程（回退）**：调用
  `E:\Anaconda\envs\CFwin11\python.exe ocr_worker/mineru_runner.py`，使用
  pipeline backend + CUDA；`mineru_runner.py` 保留上游质量覆写与 `do_parse`
  参数，并新增 `--device`。
- **PaddleOCR 已禁用**：项目位于中文路径时，Paddle C++ 无法读取模型/图片
  路径（PP-StructureV3 加载模型会报 `json.exception.parse_error.101`）。
  `select_engine()` 对 `auto` / `mineru` 都返回 `mineru`；显式 `paddle` 在
  转换入口抛出“PaddleOCR 回退已禁用”错误，不会加载 Paddle 模型。
- `OCR_ENGINE=auto|mineru|paddle`（默认 `auto`）：`auto` 与 `mineru` 都使用
  MinerU；MinerU 不可用时由转换层给出明确错误，不静默降级到 Paddle。显式
  `paddle` 直接报错。
- `MINERU_MODE=auto|api|subprocess`（默认 `auto`）：
  - `auto`：API 可用优先 API，API 失败回退子进程；
  - `api`：只用 API，不可用或失败直接报错；
  - `subprocess`：直接使用子进程。
- 所有路径输出同一契约：`out/result.md`、`out/images/`、`out/pages.json` 与
  `result.zip`，主后端与前端无感知。

### 3.3 并发、进度、超时与回退

- **并发**：`lifespan` 计算 `worker_concurrency`（显式 `OCR_WORKER_CONCURRENCY`
  优先；否则 API 可用 3、不可用 1），用 `asyncio.Semaphore` 限制同时运行的
  转换任务。模型已预热时实测 3 并发处理 3 个 16 页任务约 25s（子进程 3 并发
  约 99s）；6 并发约 46s，吞吐提升有限但需要更多显存。
- **API 进度**：提交 5 → 按已用时间 10 起步最高 90 → 下载 95 → 完成 100；
  API 未返回进度字段时仍按状态轮询推进，不会卡住。
- **子进程进度**：stdout/stderr 合并后按行读取，命中
  `layout/ocr/table/formula/markdown` 时推进到 20/45/65/75/90；无关键字时按
  已用时间缓慢推进，最高 90；完成 100。
- **超时**：API 请求默认 3600s；子进程超时后先 `terminate` 再 `kill`，任务失败
  并附带日志尾部。
- **安全**：API 结果 ZIP 解压拒绝 `..`、绝对路径（含 Windows 盘符 / UNC）与
  符号链接，防止 ZIP Slip。
- **回退**：API 失败 → 子进程（`auto`）；子进程也失败时任务失败并返回明确
  错误。PaddleOCR 回退已禁用，不会再尝试 Paddle。warning/错误写入任务
  `message`，前端可见。
- **启动**：`start.bat` 先探测 `/health`，已有健康实例直接复用，避免重复启动
  端口冲突；未运行时启动 API 并轮询最多 20 秒，失败则回退子进程模式与并发 1。
- `GET /health` 暴露实际 `engine`、`mineru_available`、`mineru_mode`、
  `mineru_api_available`、`mineru_api_url`、`worker_concurrency` 与两个路径；
  `POST /convert` 新增可选 `engine` 表单字段（主后端不传，使用配置）。

### 3.4 Markdown 与页码

- MinerU 的 `result.md` 直接归一化为 `out/result.md`，`images/` 保持
  `images/xxx.jpg` 引用；`mineru_out/` 中间产物成功后删除。
- `pages.json` 由 `content_list` 生成：按顺序在 Markdown 中查找每个区块的
  `text` / `img_path` / `table_body` 首次命中位置作为页起点，下一页起点作为
  上一页终点；页面尺寸取 `middle.json` 的 `pdf_info[].page_size`。
- 命中率低于 30%（版本差异或内容被重排）时按页数均分 Markdown 长度兜底；
  缺失 `middle.json` 时页面尺寸为 0，前端仍可标注。
- 历史 Paddle 拼接逻辑仍保留在代码中，但当前流程不会执行；`pages.json`
  统一由 MinerU 的 `content_list` 生成。
- 公式默认可选；高精度模式（`MINERU_HIGH_ACCURACY=1` 或 `dpi >= 300`）把
  `parse_method=auto` 解析为 `ocr`，优先识别扫描件。

### 3.5 批量导入与夜间串行队列

- 上传接口的 `defer_conversion=true` 只入库，不立即提交 Worker。文件先以内部
  `uploading` 状态落库，源文件写完且文件头校验通过后才切换为 `uploaded`，
  避免队列认领“半截 PDF”。`uploading` 记录不出现在项目文件列表中；服务启动时
  `cleanup_stale_uploads()` 会删除崩溃残留的 `uploading` 记录。
- `services/queue_service.py` 扫描所有项目中 `status="uploaded"` 的文件，按
  `queue_seq` 升序逐个转换；默认 `MIX_CONVERSION_CONCURRENCY=1`，严格串行。
  扫描结果缓存在 worker 内，用 `asyncio.to_thread` 读取，避免阻塞事件循环。
- 队列状态完全持久化在 `meta.json`：`queue_seq` 在导入时生成且不对外暴露；
  服务重启时 `requeue_interrupted_conversions()` 把残留 `converting` 退回
  `uploaded`，随后队列自动续跑。
- 队列执行前探测 OCR Worker `/health`；不可用时暂停等待（默认 30 秒），文件保持
  排队。连接类/5xx 失败按 `MIX_QUEUE_MAX_RETRIES`（默认 3）重试；4xx 业务错误
  直接标记失败并继续下一个，避免坏文件占住队首。
- 队列内单文件识别超时由 `MIX_QUEUE_TASK_TIMEOUT_SECONDS` 控制（默认 3600 秒），
  超时标记失败后继续下一个；普通立即转换仍使用 6 小时超时。
- 队列被取消时通过转换令牌把当前文件退回 `uploaded`，下次启动继续；单文件转换
  完成时清零重试计数并清空转换令牌。
- 前端 UploadPanel 支持目录选择与目录拖拽；按 `webkitRelativePath` 自然排序，
  逐个 `await` 上传，同名文件（含不同子目录）跳过。文件列表轮询在 pending ≤ 8 时
  逐文件查询状态，大于 8 时每轮改为一次项目详情请求，避免几十上百个文件造成请求风暴。

## 4. 切块与页码

主应用新增 `block_service`，把 `result.md` 切为顶级块：

- 类型：标题、段落、列表、表格、图片、代码、引用、HTML。
- 每块记录稳定 ID（`b0001`）、原文切片、纯文本、字符区间、页码、所属章节号（如 `3.1`、`附录A`）。
- 块 ID 按顺序生成；Markdown 修改后重新切块，旧段落标注失效。
- `pages.json` 缺失时页码为 0，前端显示“—”，不影响标注。

## 5. 前端页面

单页应用 `/`：

- 左侧：项目选择/创建、实体标签、关系类型、单文件上传、**整文件夹批量导入**、
  文件列表与项目队列进度。
  - **导入标签**：实体标签区提供「导入标签」入口，汇总所有项目（排除当前项目）用过的
    实体标签与引用次数，弹窗内可搜索、全选、逐个勾选；已存在的标签只展示不可选。
    导入复用字典增量保存链路（`labels_add`），不会覆盖当前项目已有标签。
- 中间：Markdown 工作区。
  - **编辑模式**：源码 textarea + 渲染预览；应用修改后重建 blocks。
  - **标注模式**：逐块渲染 Markdown；直接框选一个或多个自然段，整个选区作为一个标注，点击标签应用；不再有逐段 gutter。
  - **按页对齐**：Markdown 与 PDF 以 blocks 的 `page/pageEnd` 为锚点，把每页页首换算成两侧滚动偏移；
    滚动时先定位所在页，再在页内按比例插值，跨多页的累计偏差会被页首锚点校正。
    工具条按钮为「按页对齐」；编辑模式没有块锚点，回退为整体比例同步。
- 右侧：原始 PDF / 原图预览，带页码、缩放、拖框截图与已有图表叠加层。
- 顶部：品牌、当前项目、保存、导出 ZIP。

## 6. 标注交互

### 6.1 实体与关系（沿用）

- `markdown-it` 渲染 + `DOMPurify` 清洗；遍历 DOM 文本节点建立 `canonical text` 偏移。
- 实体高亮使用 CSS Custom Highlight API；关系曲线用 SVG 叠加。
- 每处实体高亮的**首行上方**叠加一枚标签名胶囊（沿用字典 chip 底色，高 14px、字号 10.5px），
  解决 40–50 个标签下 6 色调色板重复、只看底色无法辨认的问题。胶囊层是纯视觉投影
  （`aria-hidden`；胶囊本身可点击选中对应实体），不参与正文命中测试、不影响 canonical 偏移。
  多行实体只在首行出现一次；密集/嵌套实体按「行首 → 同行向右紧邻 → 右对齐 → 上移错开」避让。
- 胶囊可点击：点哪枚就选中哪处标注（同一范围有多个标签时选最新一条），
  不会因为事件穿透选中上一行的相邻实体。
- 同一段文本被重复标注时，一个范围只画一枚胶囊：完全重复的记录（同范围 + 同标签）在读取时合并、
  关系指向自动改指保留项；同范围不同标签合并显示为「最新标签 +N」，悬停可看全部标签，
  不再在同一段文字上叠出两三枚名字。重新框选这段文本并应用一次标签，会把该范围的旧标签收敛成一条。
- 工具条提供「标签名：全部 / 选中 / 隐藏」三段开关，偏好写入 `localStorage`
  （`labelfast.spanLabelMode`）；「选中」模式在未选中实体时只显示一条空态提示。
- 选中文本后点击实体 chip 或按 `1–9`；关系 chip 或 `Ctrl+1–9`。
- 打实体标签时记录所在段落的 `blockId`。

### 6.2 跨自然段选区标注

- 不再使用逐段 gutter；用户直接框选一个或多个自然段，整个选区生成一个 span，
  点击标签应用到整个选区。
- 后端 blocks 仍用于逐块渲染、页码与章节映射；span 的 `blockId` 取选区起始块。
- 逐块渲染的 canonical text 与整篇渲染保持一致，旧 span 偏移不漂移。
- 编辑 Markdown 时提示：实体/关系标注将清空，图表记录保留。历史 `paragraphs`
  字段仅保留后端兼容，不再由 UI 产生。

### 6.3 图片 / 表格截图

- 在 PDF 预览中开启“截图”模式，拖框选区。
- 入口按钮位于预览头部右侧，按「导出 ZIP」同一套主按钮样式（实心 signal 橙、36px 高）放大展示；
  快捷键 **F3**（预览未打开时按 F3 会先打开预览并排队进入截图模式，再按一次退出）。
  F3 为系统保留键，不允许绑定到实体标签（设置时会提示「已被图片／表格标注占用」）。
  编辑模式、弹窗打开或输入框聚焦时 F3 不生效。之所以不用 F1：浏览器会先用 F1 打开帮助页，页面层拦不住。
- 前端把 CSS 像素换算为 PDF pt（左上原点）或图片像素，记录 page + bbox。
- **乱码文本层自动兜底**：老国标 PDF 常见字体编码缺少 ToUnicode 映射，文本层直接提取出来是
  `! "# $ % &` 这类符号串。转换前会抽样读取 PDF 文本层并检测（汉字≈0、标点占比极高、
  字母不成词），命中时自动用 `parse_method=ocr` 整页识别并把提示写进转换结果；
  已经生成乱码 Markdown 的历史文件，画布顶部会显示「重新 OCR 转换」入口（会清空该文件的标注）。
- 确认时以 200 DPI 离屏渲染当前页并裁剪为 PNG；扫描件同样可用。
- 弹窗只填写类型（图/表）、标题与备注；图表不设编号、标签，也不归属任何段落。
- **按文件重新 OCR**：模块头「导入数据」右侧提供「重新 OCR」按钮，弹窗内可调
  识别精度（DPI 200/300/400）、解析方式（自动 / 强制 OCR / 仅文本层）、表格与公式识别；
  默认预填偏高的推荐值（300 DPI + 表格识别 + 自动解析），每项都带场景说明。
  提交走 `POST /api/files/{id}/convert`，`parse_method` 透传到 MinerU；
  重新转换会清空该文件的实体/关系标注与图表截图，弹窗内已明确告警。
- **标题自动预填**：新建图表时把框选截图发给 OCR Worker 的小图 OCR
  （`POST /ocr/region`，RapidOCR/ONNXRuntime，模型内置、离线可用；截图会做留白 + 2 倍放大，
  提升小字号标题的检出率），从文字行里提取「图 3 XXXX / 表 2 XXXX」并填入标题；
  标题以「图 / 表」开头时同步把类型切到对应项（用户已手动选过类型则不覆盖）；
  识别不可用时只提示手动填写，不阻塞创建。提取逻辑在 `services/caption_service.py`，
  前端只在标题未被手动编辑时自动覆盖。
- 弹窗左侧截图可点击放大（按视口 92% 宽 / 86% 高等比放大，点击任意处或 Esc 关闭），
  便于核对截图细节。
- 图表资产存放于文件级 `assets/figures/`，重新 OCR 不删除；页面叠加层可点选编辑/删除。

## 7. 数据与导出

- 项目/文件元数据：JSON 文件；无数据库。文件元数据内部增加 `queue_seq`
  （导入顺序）与 `queue_retry_count`（服务故障重试计数），均不对外暴露、不参与导出。
- 标注：每文件一个 `annotations.json`，包含 `text/spans/relations/paragraphs/figures`。
- 图表通过独立接口 CRUD；`PUT /annotations` 自动保留 figures。
- 图表记录只保留 `id/kind/caption/note/page/bbox/assetPath`（内部另含
  `created_at/updated_at`）；旧数据中的 `number/label/paragraphId` 在读取、
  更新与导出时忽略并剔除，不报错。
- 重新 OCR 或编辑 Markdown：清空文本/段落标注，保留图表记录与资产。
- 导出 ZIP（路径统一使用上传文件名，不加内部 id；同名文件依次 `_2`、`_3`）：
  - `annotations.jsonl`：兼容旧知识库，新增 paragraphs/figures/pages/meta；
  - `graph.jsonl`：document / section / paragraph / figure / table / entity 节点与层级/关系边；
    图表节点 `label` 固定为 `图`/`表`，`name` 取 caption，不再输出段落归属边；
  - `original/<文件名>.<ext>`、`markdown/<文件名>.md`（多文件为
    `markdown/<文件名>/<文件名>.md` + `images/`）、`blocks/<文件名>.json`；
  - `assets/<文件名>/`：图表截图（`fig_0001.png` / `tbl_0001.png`）；
  - `manifest.json`：版本与文件/资产清单。

## 8. 知识库对接

- 知识库 `jsonl_import.py` 识别 `graph.jsonl`（首行 `record=meta` 或 `format=labelfast-hybrid/v2`）。
- 节点 id 加 `lf:` 前缀并保留显式 id；`attributes` 转 `{key,value}`；层级边映射为 `parent-child`。
- 导入 summary 带 `preserve_ids=true`，前端按节点 id 合并，避免同名段落被错误合并。
- 资产路径保存在节点 `asset_path` 属性；后续知识库增加资产根目录配置即可展示。

## 9. 部署（旧方案，当前未使用）

> Win11 + CFwin11 + MinerU，Paddle 回退已禁用，旧镜像不再符合当前 OCR 流程；

## 10. 风险

- MinerU 在复杂表格/公式上的质量需要用真实 PDF 验收。
- MinerU 首次运行需加载模型到显存，单任务延迟较高；Paddle 兜底已禁用，
  API 与子进程都失败时任务会直接失败，需要关注 MinerU 健康状态。
- MinerU 的 `content_list` 定位依赖 Markdown 引用形式；版本升级后命中率可能
  下降，此时 `pages.json` 退化为均分页码（字符区间可用但页边界可能偏移）。
- 逐块渲染依赖后端切块准确；OCR 正常输出块间有空行，若出现 lazy continuation 需抽查。
- 图表不再与段落建立归属关系，避免 OCR 切块变化导致归属错位；需要定位时以页码 + bbox 为准。
- CPU-only 在 Win7 虚拟机上的速度需要实测；必要时降低 DPI、关闭公式/表格，或换服务器。
- 编辑 Markdown 后段落/实体标注失效；通过分模式与确认提示规避静默错位。
