# 混合标注：项目按文件区间拆分 + 项目级自定义快捷键

> 模块：`mixed_annotation` + `frontend/src/modules/mixed-annotation`
> 依据用户确认：拆分 = **按文件序号区间** 一次拆成多个新项目；文件**移动**、源项目不保留；新项目**全量继承**字典；快捷键**每个项目一套**、项目之间互不干扰。

## 1. 项目拆分

### 1.1 交互

入口：顶栏「设置」菜单 →「拆分项目」。

弹窗列出当前项目文件总数 N（顺序与左侧文件列表一致，1 基），用户添加若干行：

| 起始 | 结束 | 新项目名称 |
| --- | --- | --- |
| 1 | 30 | 国标3-A |
| 31 | 50 | 国标3-B |

- 每行至少 1 个文件，`1 ≤ start ≤ end ≤ N`；
- 行之间区间不得重叠；允许留空（未分配文件留在源项目）；
- 新项目名称必填、1–120 字、本次提交内不得重名；
- 选中的文件若处于 `converting` 状态，禁止提交并提示文件名；
- 若区间覆盖全部文件，弹窗内提示“源项目将不再包含任何文件”；
- 提交成功后：刷新项目列表，自动切到第一个新项目，提示“已拆分为 N 个项目，移动 M 个文件”。

### 1.2 后端接口

```
POST /api/projects/{project_id}/split
{
  "groups": [
    {"name": "国标3-A", "start": 1, "end": 30},
    {"name": "国标3-B", "start": 31, "end": 50}
  ]
}
```

响应：

```json
{
  "projects": [
    {"project": { ...完整 Project... }, "file_count": 30, "file_ids": ["..."]}
  ],
  "source_project": { ...完整 Project... }
}
```

语义：

- 文件序号以 `list_files(project_id)` 的顺序为准（`created_at` 倒序、`queue_seq` 兜底），并**排除 `status == "uploading"`**（与 `GET /projects/{id}` 返回的 files 一致）；
- 每个分组创建一个新项目：**全量继承** `labels`、`relation_types`、`shortcuts`；
- 文件以**移动**方式进入新项目：整个文件目录（source、markdown、assets、figures、blocks、pages、annotations.json、meta.json）一起移动，`meta.json` 的 `project_id` / `dir_name` / `updated_at` 更新，文件 id 不变；
- 目标项目内目录名按现有 `_dedupe_dir_name` 规则去重；
- 全部操作加 `_LOCK`，**要么全成功要么全回滚**：任一步失败，已移动文件移回源项目、已创建项目删除，再抛出带中文 detail 的 `ServiceError`；
- 校验失败返回 400；文件正在转换返回 409；项目不存在 404；
- 源项目文件变化不修改源项目的字典与 `shortcuts`。

### 1.3 校验（后端）

- `groups` 非空、最多 50 组；
- 每组 `name` 去空白后非空且 ≤120 字，组内名称不得重复；
- `start`/`end` 为整数，`1 ≤ start ≤ end ≤ N`；
- 任意两组区间不得重叠（端点相同也算重叠）；
- 被选中的文件不得是 `converting`（`uploading` 已被排除，`uploaded`/`completed`/`failed` 可移动）。

## 2. 项目级自定义快捷键

### 2.1 数据模型

`project.json` 新增字段 `shortcuts: {"标签名": "快捷键"}`，只保存**用户显式设置过的覆盖项**；默认规则仍为「前 9 个标签 → 数字 1–9」。

有效快捷键 = 默认 1–9 + 覆盖项（覆盖项优先，同一标签只保留一个）。项目之间完全独立。

按键格式（规范化后存储）：

- 单键：`1`、`q`（字母统一小写）、`!`、`F2`；
- 组合键：`Ctrl+K`、`Alt+Shift+P`，修饰键顺序固定 `Ctrl+Alt+Shift`；
- 禁止：`Escape`、`Delete`、`Backspace`、`Enter`、`Tab`、`Space`、四个方向键、`Home`/`End`/`PageUp`/`PageDown`、`Ctrl+Z`、`Ctrl+S`、`Ctrl+1`…`Ctrl+9`（关系快捷键）。

### 2.2 后端接口

复用 `PATCH /api/projects/{project_id}`，新增：

```json
{
  "shortcuts_set": {"适用范围": "q", "机械性能": "Ctrl+K"},
  "shortcuts_unset": ["实验步骤"]
}
```

语义：

- `shortcuts_set`：逐项覆盖；标签必须存在于当前项目字典，否则 400；
- `shortcuts_unset`：删除覆盖项，回落到默认（前 9 个标签）或“无快捷键”；
- 同一次请求内先计算合并后的字典（含 `labels_add`），再校验标签归属；
- 合并后计算**有效快捷键**，任两个标签对应同一组合 → 409，detail 列出冲突标签；
- 删除标签（`labels_remove`）时同步删除该标签的快捷键覆盖项；
- 项目创建/拆分时继承 `shortcuts`（新项目默认 `{}`）；
- 响应返回完整项目对象（含 `shortcuts`）。

### 2.3 前端交互

- 左侧「标签与关系」卡片头部新增「快捷键」按钮，打开 `ShortcutSettingsDialog`；
- 对话框列出全部标签，显示当前有效快捷键与来源（默认 / 自定义）：
  - 每行「录制」：点击后进入录制态，下一次按键立即绑定；`Esc` 取消录制；
  - 每行「清除」：删除自定义覆盖，回落到默认或“无”；
  - 冲突/保留键错误就地显示，保存按钮禁用；
- 保存时一次性提交 `shortcuts_set`（所有自定义覆盖）与 `shortcuts_unset`（被清除的标签），成功后用响应回写 `currentProject.shortcuts`；
- 标注画布的标签 chip 徽标改为显示**有效快捷键**（不再只是下标 1–9）；超过 9 个的标签未设置时显示“无快捷键”样式；
- `useMarkdownAnnotation` 的按键处理：
  - 保留现有 `Ctrl+Z` 撤销、`Delete` 删除、`Escape` 取消、`Ctrl+1–9` 关系；
  - 选中文本后，按当前项目的有效快捷键应用对应标签；
  - 在输入框/文本域/可编辑区域内不触发（沿用现有判断）。

## 3. 测试与验收

后端：

1. 新建项目默认 `shortcuts == {}`；
2. 设置/清除覆盖、默认 1–9 生效、冲突 409、保留键 400、标签不存在 400；
3. 删除标签时清理对应快捷键；
4. 按区间拆分：文件正确移动、id 不变、标注仍可读取、新项目继承字典与 shortcuts、源项目剩余文件正确；
5. 区间重叠/越界/重名/空组 → 400；含 converting 文件 → 409 且不产生任何新项目；
6. 移动中途失败 → 回滚（源项目文件恢复、新项目删除）。

前端：

- `npm run typecheck`、`vite build` 通过；
- 弹窗在真实浏览器打开、校验提示正确、录制按键与新 chip 徽标正常；
- 不修改真实项目数据做破坏性验证（可用临时项目，完成后删除）。

## 4. 已知边界

- 拆分是同步文件移动，大项目（数百文件、GB 级）会有可感知等待；接口返回前不提供进度条；
- 拆分不复制文件，源项目一旦移空仍会保留（用户可自行删除）；
- 快捷键为项目级共享，两人同时修改以最后一次 PATCH 为准（字典已做增量合并，快捷键同样按 set/unset 增量提交，不会整份覆盖）。
