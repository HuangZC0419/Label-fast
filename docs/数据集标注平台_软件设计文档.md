## 1. 引言

### 1.1 编写目的

本文档旨在对"数据集标注平台"进行全面的软件设计说明，涵盖系统架构、功能模块、数据模型、接口规范、前端设计、安全策略以及部署方案等各个方面。本文档面向软件开发人员、系统运维人员、项目管理人员以及后续的维护和扩展团队，作为理解系统设计、进行二次开发和技术评审的核心参考依据。

### 1.2 项目背景

在人工智能与深度学习领域，高质量的标注数据是模型训练的基础。无论是自然语言处理（NLP）领域的命名实体识别、关系抽取，还是计算机视觉（CV）领域的物体检测、图像问答，都需要大量经过人工标注的数据作为训练样本。然而，现有的标注工具普遍存在以下问题：

- **标注类型单一**：多数工具仅支持文本标注或图像标注中的一种，缺乏统一平台；
- **部署复杂**：依赖外部数据库、在线CDN资源，在内网或离线环境中难以部署；
- **数据流转繁琐**：标注完成后的数据导出格式不统一，难以直接对接模型训练管线；
- **协作能力弱**：缺乏用户认证与项目管理机制，多人协作时数据容易混淆；
- **操作效率低**：缺少高效的快捷键体系和批量操作能力。

基于上述痛点，本平台设计并实现了一套集文本标注与图像标注于一体的综合性数据标注系统，支持实体标注、关系标注、图像问答标注、图像框选标注等多种标注范式，并提供统一的项目管理、用户认证、多格式数据导出和容器化部署能力，为深度学习模型的训练数据生产提供全流程支持。

### 1.3 适用范围

本平台适用于以下场景：

- **自然语言处理（NLP）数据标注**：命名实体识别（NER）、关系抽取（RE）、事件抽取等任务的训练数据生产；
- **计算机视觉（CV）数据标注**：物体检测（Object Detection）的边界框标注、视觉问答（VQA）的问答对标注；
- **多模态模型训练数据准备**：同时需要文本与图像标注的跨模态任务；
- **团队协作标注**：支持多用户通过认证机制在同一平台上分工标注不同项目；
- **离线/内网环境部署**：通过容器化方案，可在无互联网访问的服务器上独立运行。

## 2. 系统概述

### 2.1 系统定位

数据集标注平台是一套面向深度学习数据标注场景的综合型Web应用系统。系统采用前后端分离的B/S架构，提供文本标注与图像标注两大核心功能模块，支持从数据导入、标注执行、质量管控到多格式导出的全流程闭环。

### 2.2 核心能力

本平台具备以下核心能力：

1. **文本实体标注**：支持在文本中通过鼠标拖选方式标注命名实体，并以不同颜色高亮显示不同实体类别；
2. **文本关系标注**：支持在已标注实体之间建立有向关系，以贝塞尔曲线可视化呈现，支持多种关系类型；
3. **图像框选标注**：支持在图像上拖拽绘制矩形边界框，以不同颜色区分不同目标类别，支持多标签体系；
4. **图像问答标注**：支持为每张图像编写用户指令（User Prompt）和助手回答（Assistant Response），生成标准的多模态对话训练数据；
5. **统一项目管理**：文本标注与图像标注共享项目概念，支持项目创建、切换、删除及配置管理；
6. **多格式导出**：支持JSON结构化格式、JSONL逐行格式、CSV/TSV表格格式以及ZIP打包导出；
7. **用户认证**：基于JWT令牌的认证体系，支持Excel文件管理用户账号；
8. **容器化部署**：通过Docker多阶段构建，支持在线和离线两种部署模式；
9. **离线运行**：图像标注前端使用本地静态资源（Vue.js、Tailwind CSS），不依赖外部CDN，确保内网环境可用。

### 2.3 技术路线

| 层次 | 技术选型 | 说明 |
|------|---------|------|
| 后端框架 | Python FastAPI | 高性能异步Web框架，自动生成API文档 |
| ORM框架 | SQLAlchemy 2.0 | Python生态最成熟的ORM框架 |
| 数据库 | SQLite 3 | 嵌入式数据库，零配置，适合单机部署 |
| 前端框架（文本） | React 18 + TypeScript | 组件化开发，类型安全 |
| 前端框架（图像） | Vue.js 3 + Tailwind CSS | 响应式设计，快速开发 |
| 构建工具 | Vite 5 | 新一代前端构建工具 |
| 认证方案 | PyJWT (HS256) | 基于JWT的无状态认证 |
| 容器化 | Docker + docker-compose | 多阶段构建，环境一致性 |
| Web服务器 | Uvicorn | ASGI服务器，支持热重载 |

### 2.4 系统边界

本平台聚焦于数据标注环节，不包含模型训练和推理功能。系统的输入为原始文本文件和图像文件，输出为结构化标注数据文件（JSON/JSONL/CSV/ZIP）。平台通过浏览器提供交互界面，用户通过鼠标操作和键盘快捷键完成标注工作。

### 3.2 后端架构

#### 3.2.1 应用入口与挂载

后端基于FastAPI构建，`server.py`为主入口文件。FastAPI应用实例`app`作为顶层应用，同时通过`app.mount("/minimind", minimind_app)`将图像标注子系统挂载到`/minimind`路径下。这种挂载设计使得两个子系统可以独立开发和测试，但在部署时合并为统一的服务，共享端口和中间件。

#### 3.2.2 中间件层

系统注册了三层中间件，按注册顺序形成洋葱模型：

1. **CORS中间件**（最外层）：允许任意来源的跨域请求（`allow_origins=["*"]`），确保前后端分离部署时不被浏览器同源策略阻止。在生产环境中应替换为具体的允许域名。

2. **JWT认证中间件**：拦截所有`/api/*`路径的请求，验证`Authorization: Bearer <token>`头中的JWT令牌。以下路径被排除在认证之外：
   - `/api/auth/*`：登录注册相关接口
   - `/api/health`：健康检查接口
   - 所有非`/api/*`路径：静态资源和前端页面

3. **前端SPA中间件**（条件注册）：仅在前端构建产物存在时注册。将非`/api/`和非`/minimind`的GET请求路由到前端SPA的`index.html`，实现HTML5 History模式的前端路由支持。

#### 3.2.3 业务服务层（分层架构）

后端遵循分层架构原则，从下到上分为三个层次：

**存储层（storage/）**：
- `db.py`：数据库连接管理，提供`init_db()`初始化函数和`get_session()`会话工厂；
- `schema.py`：SQLAlchemy ORM模型定义，包含`Project`、`Document`、`Annotation`、`Relation`、`User`五个实体。

**服务层（services/）**：
- `auth_service.py`：用户认证与JWT令牌管理
- `project_service.py`：项目CRUD及配置管理
- `document_service.py`：文档（待标注文本）管理
- `annotation_service.py`：标注（实体Span）的增删改查
- `relation_service.py`：关系标注的增删改查
- `import_service.py`：TXT文件导入与文本切分
- `export_service.py`：标注数据多格式导出
- `sync_service.py`：项目完整数据的加载与保存（用于前端同步）
- `record_service.py`：标注记录的JSONL文件追加存储

**模型层（models.py）**：
- 使用Pydantic定义数据传输对象，包括`ProjectModel`、`DocumentModel`、`AnnotationModel`、`RelationModel`，确保API层与服务层之间的数据契约清晰。

#### 3.2.4 图像标注子系统

图像标注子系统是一个独立的FastAPI应用（`图像标注器/label_system/app.py`），通过`app.mount("/minimind", minimind_app)`挂载到主应用下。其内部架构包括：

- **项目管理**：通过`projects.json`文件维护项目索引，每个项目对应独立的文件系统目录；
- **内存配置**：使用全局变量维护当前活动项目的配置信息，包括图片目录、JSONL输出路径等；
- **文件存储**：问答标注和框选标注分别存储为`标注结果_qa.jsonl`和`标注结果_boxes.jsonl`；
- **数据格式**：问答标注采用`{"conversations": [...], "image": "..."}`的多轮对话格式；框选标注采用`{"image": "...", "boxes": [...]}`的边界框格式。

### 3.3 前端架构

#### 3.3.1 文本标注前端

文本标注前端采用React 18 + TypeScript + Vite技术栈，主要组件树如下：

```
App (BrowserRouter + AuthProvider)
├── LoginPage           — 登录页面（GuestOnly守卫）
├── RootRedirect        — 根路径认证状态路由
└── AnnotatorApp        — 主工作区（RequireAuth守卫）
    ├── Header          — 顶部导航栏（项目信息、用户信息、图像标注入口）
    ├── Sidebar         — 左侧边栏
    │   ├── 项目配置模块  — 项目选择/创建/保存/导出/删除
    │   ├── 标签配置模块  — 实体标签/关系类型配置，TXT导入
    │   └── 待标注对象模块 — 文档列表、上传拖拽区、切分方式选择
    ├── Workspace       — 中央工作区
    │   ├── 工具栏       — 上一篇/下一篇/跳过/保存/删除
    │   ├── 标签快捷键区  — 实体标签按钮面板 + 关系类型按钮面板
    │   └── 文本标注区    — 字符级渲染文本 + SVG标注覆盖层
    ├── SettingsModal   — 显示设置弹窗（字体/行高/关系线宽）
    ├── HelpModal       — 切分方式帮助弹窗
    └── Label/RelPicker — 浮动标签/关系选择器
```

核心设计决策：
- **字符级渲染**：将文本拆分为单个字符的`<span>`元素，通过绝对定位覆盖彩色标注块，实现精确的字符级标注定位；
- **SVG关系连线**：使用SVG的贝塞尔曲线（C命令）绘制实体间的关系连线，支持悬停高亮、箭头标记、虚线样式等；
- **Ref模式避免闭包陷阱**：键盘事件监听器使用`useRef`存储最新状态引用，避免`useEffect`依赖数组膨胀导致的频繁重绑定问题；
- **认证上下文**：通过React Context提供全局认证状态，`AuthProvider`在应用根层注入认证信息。

#### 3.3.2 图像标注前端

图像标注前端是一个独立的单文件Vue.js 3应用（`label_system/templates/index.html`），采用Composition API + Tailwind CSS实现。主要功能模块包括：

- **Header**：品牌Logo、文本标注平台入口、标注进度统计（已标注/总数）；
- **左侧边栏**：
  - 项目配置区：历史项目下拉选择、新建项目输入框、项目路径信息展示（只读）；
  - 图片列表区：以列表形式展示项目中的所有图片，已标注图片显示绿色勾号标记；
- **右侧工作区**：
  - 图像显示区：支持图片加载与自适应缩放显示；
  - 标注模式切换（问答标注/框选标注）；
  - 问答标注模式：用户指令输入框 + 助手回答输入框 + 保存并下一张按钮；
  - 框选标注模式：标签管理（添加/选择/删除标签）、框选绘制按钮、已绘制框列表、保存/导出按钮。

核心设计决策：
- **Pointer Events精确定位**：使用HTML5 Pointer Events API实现图像的框选拖拽标注，支持触摸和鼠标操作；
- **坐标系统转换**：在图像原始像素坐标与屏幕显示坐标之间进行精确转换，确保在不同缩放和布局下标注框位置准确；
- **图片子目录支持**：递归扫描`images/`目录及其子目录，支持按文件夹组织大量图片；
- **标注数据即时加载**：切换项目时自动加载对应项目的问答和框选标注记录，确保标注数据的项目隔离。

### 3.4 数据存储架构

系统采用混合存储策略：

1. **SQLite关系数据库**（`文本标注器/storage/文本标注器.db`）：
   - 存储文本标注的核心业务数据：项目、文档、标注、关系、用户；
   - 提供事务性保证和SQL查询能力。

2. **JSONL文件存储**（`projects/<项目名>/`）：
   - 存储标注记录的快照（annotations.jsonl），用于数据持久化备份和导出；
   - 采用追加写入（append）模式，每条标注记录为一行JSON；
   - 作为"保存并下一篇"操作的主数据源，与数据库同步写入。

3. **JSON索引文件**（`projects.json`）：
   - 存储图像标注项目的元数据索引，包含项目ID、名称、路径、标签列表等信息。

4. **文件系统目录**：
   - `projects/<项目名>/images/`：图像标注项目的原始图片存储；
   - `projects/<项目名>/imports/`：文本标注项目的原始文本文档存储；
   - `projects/<项目名>/exports/`：标注数据导出存储。

## 4. 功能模块设计

### 4.1 用户认证模块

#### 4.1.1 功能概述

用户认证模块负责系统的身份验证和访问控制。系统采用基于JWT（JSON Web Token）的无状态认证机制，用户凭据通过Excel文件（`users.xlsx`）管理。

#### 4.1.2 认证流程

```
用户输入用户名密码
        │
        ▼
 POST /api/auth/login
        │
        ▼
  auth_service.login_user()
        │
        ├─ 查找 Excel 用户表
        ├─ 验证密码匹配
        ├─ 生成 JWT Token (HS256, 有效期7天)
        └─ 返回 {token, user}
        │
        ▼
 前端存储 Token 到 sessionStorage
        │
        ▼
 后续请求携带 Authorization: Bearer <token>
        │
        ▼
 JWT认证中间件拦截 /api/* 请求
        │
        ├─ 解析并验证 Token 有效性
        ├─ 验证通过 → request.state.user_id 注入
        └─ 验证失败 → 401 Unauthorized
```

#### 4.1.3 JWT密钥管理

系统采用三级优先级的JWT密钥管理策略：

1. **环境变量**`JWT_SECRET`（最高优先级）：支持Docker等外部环境注入；
2. **`.env`文件**中的`JWT_SECRET`：持久化密钥，确保服务重启后Token仍然有效；
3. **自动生成**：若以上均不存在，自动生成32字节安全随机密钥并持久化到`.env`文件。

#### 4.1.4 用户管理

用户账号存储在`backend/users.xlsx`文件中，表结构如下：

| 列名 | 说明 | 必填 |
|-----|------|------|
| username | 登录用户名 | 是 |
| password | 登录密码（明文） | 是 |
| role | 用户角色 | 否 |
| name | 用户显示名称 | 否 |

系统启动时一次性加载所有用户到内存字典中，登录时直接比对，无需数据库查询。此设计简化了部署配置，管理员可直接用Excel编辑用户账号。

### 4.2 文本标注模块

文本标注模块是系统的核心功能之一，专注于自然语言处理（NLP）领域的数据标注。

#### 4.2.1 项目配置管理

**项目创建**：
- 用户输入项目名称，系统自动创建项目记录和对应的文件系统目录；
- 支持配置实体标签列表（逗号分隔）和关系类型列表（逗号分隔）；
- 支持从TXT文件批量导入标签和关系配置。

**项目切换**：
- 下拉选择已有项目，系统自动加载完整的项目数据（文档、标注、关系）到前端；
- 切换前自动保存当前项目的编辑状态，防止数据丢失。

**项目管理**：
- 保存项目：将当前所有文档、标注、关系同步到数据库，同时备份文本到文件系统；
- 清空项目：删除项目下的所有文档、标注和关系数据，保留项目元数据；
- 删除项目：彻底删除项目记录、关联数据和文件系统目录。

#### 4.2.2 文本导入与切分

系统支持通过拖拽或文件选择方式导入`.txt`文本文件，并提供三种文本切分策略：

| 切分模式 | 策略 | 适用场景 |
|---------|------|---------|
| 原文模式（as_is） | 整篇不切分，全文作为一个标注对象 | 短文本标注、完整文档分析 |
| 段落模式（paragraph） | 按空行（`\n\n`）分段落 | 结构化文档、内容分段分析 |
| 句子模式（sentence） | 按句末标点（。．.！？!?）切分 | 句子级实体识别、语法分析 |

**编码检测**：系统使用`charset-normalizer`自动检测文件编码（UTF-8、GBK、UTF-16等），无需用户手动选择编码格式。前端也内置了客户端编码尝试逻辑（TextDecoder多编码尝试）。

#### 4.2.3 实体标注

**交互方式**：
1. **鼠标拖选**：用户在文本上按住鼠标左键拖选文字区间，释放后弹出标签选择器；
2. **快捷键选择**：选中文字后，按数字键1-9快速选择对应的实体标签；
3. **空格键确认**：选中文字后按空格键，自动选择第一个标签并确认。

**标注渲染**：
- 采用字符级渲染（每个字符一个`<span>`元素），通过`getBoundingClientRect()`获取每个字符的屏幕坐标；
- 在文本上方覆盖绝对定位的半透明矩形块，不同标签使用不同颜色；
- 当前选中的实体使用深色边框高亮显示。

**业务规则**：
- 标注区间的起止位置必须在文本长度范围内；
- 实体标签必须在项目配置的标签列表中；
- 默认不允许标注区间重叠（可通过`allow_overlap`配置项切换）；
- 删除实体时自动级联删除其关联的所有关系标注。

**操作支持**：
- 删除（Delete键）：删除当前选中的实体及其关联关系；
- 右键切换：在有多个重叠实体的字符上右键可循环切换选中实体；
- 撤销（Ctrl+Z）：撤销最近一次标注操作。

#### 4.2.4 关系标注

**交互方式**：
1. **拖拽连线**：在一个实体上按下鼠标，拖拽到另一个实体上释放；
2. **点击配对**：先点击第一个实体进入"选择来源"状态，再点击第二个实体完成配对；
3. **快捷键确认**：弹出关系选择器后，按Ctrl+数字键选择关系类型。

**关系可视化**：
- 使用SVG贝塞尔曲线（`C`命令）绘制实体间的关系连线；
- 连线自动计算弧形高度，避开文本内容区域；
- 悬停时连线加粗高亮，并显示关系类型标签；
- 支持虚线样式和自定义线宽设置（在设置面板中调整）。

**业务规则**：
- 关系类型必须在项目配置的关系类型列表中；
- 同类型、同方向的关系不允许重复建立；
- 关系必须建立在同一文档的标注实体之间。

#### 4.2.5 标注数据保存与同步

**"保存并下一篇"流程**：
1. 前端收集当前文档的文本、实体标注和关系标注；
2. 构造包含`id`、`text`、`spans`、`relations`、`meta`的记录对象；
3. 通过POST `/api/projects/{project_id}/record`写入后端JSONL文件；
4. 通过POST `/api/projects/{project_id}/sync`同步到SQLite数据库；
5. 更新文档状态为"completed"（已完成），自动跳转到下一篇。

**双写策略**：
- JSONL文件写入：追加模式，不可变记录，用于数据溯源和导出；
- SQLite数据库写入：事务模式，支持回滚和查询，用于状态管理。

### 4.3 图像标注模块

图像标注模块专注于计算机视觉（CV）领域的数据标注，支持问答标注和框选标注两种范式。

#### 4.3.1 项目配置管理

**项目创建**：
- 用户输入项目名称，系统自动生成唯一ID（UUID）；
- 自动创建标准化的项目目录结构：`projects/<项目名>/images/`、`projects/<项目名>/标注结果_qa.jsonl`、`projects/<项目名>/标注结果_boxes.jsonl`；
- 项目名称在系统内全局唯一，重复创建将被拒绝。

**项目目录结构标准化**：
```
projects/<项目名>/
├── images/                    ← 用户存放待标注图片
│   ├── 001.png
│   ├── subdir/002.jpg         ← 支持子目录组织
│   └── ...
├── 标注结果_qa.jsonl          ← 问答标注记录
├── 标注结果_boxes.jsonl       ← 框选标注记录
├── imports/                   ← 文本标注导入文件
└── exports/                   ← 导出文件
```

**项目数据隔离**：
- 每个项目的标注数据完全隔离：切换项目时，前端自动从对应项目的JSONL文件加载标注数据；
- 不同项目可以有不同的标签体系，互不干扰；
- 项目删除时，同时删除`projects.json`中的索引记录和文件系统目录。

#### 4.3.2 图片管理

**图片发现**：
- 递归扫描项目`images/`目录及其所有子目录中的图片文件；
- 支持的图片格式：PNG、JPG/JPEG、BMP、GIF、WEBP；
- 返回相对于`images/`目录的路径列表，保持目录结构信息。

**图片浏览**：
- 图片列表展示所有图片的相对路径；
- 已标注图片在列表中以绿色勾号标识；
- 提供"上一张"/"下一张"导航按钮和键盘快捷键（A/D键）；
- 默认跳转到首张未标注的图片，提升标注效率。

**进度追踪**：
- 实时统计已标注图片数量和总图片数；
- 每张图片可以同时有问答标注和框选标注，任一类型存在即视为"已标注"。

#### 4.3.3 问答标注

**数据格式**：
```json
{
  "conversations": [
    {"role": "user", "content": "描述这张图片中的内容。\n<image>"},
    {"role": "assistant", "content": "图片中展示了一只在草地上玩耍的金毛寻回犬..."}
  ],
  "image": "001.png"
}
```

**交互流程**：
1. 用户在右侧面板输入用户指令（User Input）；
2. 用户在右侧面板输入期望的助手回答（Assistant Output）；
3. 点击"保存并下一张"或按Ctrl+Enter保存；
4. 系统自动在用户指令末尾追加`\n<image>`标记（如用户未手动添加）；
5. 前端自动提取并去除用户输入中的`<image>`标记，保持界面整洁。

**默认提示**：用户指令输入框预填默认提示"详细描述这张图片。"，用户可根据具体需求修改。

#### 4.3.4 框选标注

**数据格式**：
```json
{
  "image": "001.png",
  "boxes": [
    {"x1": 120.5, "y1": 80.3, "x2": 350.8, "y2": 290.1, "label": "dog"},
    {"x1": 400.0, "y1": 150.2, "x2": 520.6, "y2": 320.5, "label": "cat"}
  ]
}
```

**交互流程**：
1. 用户在右侧面板管理标签：输入标签名按Enter添加，点击已有标签选择当前活动标签，支持数字快捷键1-9/0快速选择；
2. 点击"开始框选标注"按钮或按数字快捷键自动激活绘制模式；
3. 在图片上按住鼠标左键拖拽绘制矩形框，释放鼠标完成标注；
4. 框的最小尺寸为3像素，小于此阈值视为误触自动取消；
5. 已绘制的框在右侧列表显示坐标和标签信息，支持单独删除或清空全部框。

**坐标系统**：
- 标注坐标基于图像的原始像素尺寸（naturalWidth × naturalHeight）；
- 前端自动处理图像缩放和偏移，在显示时将图像像素坐标转换为屏幕绝对定位坐标；
- 确保无论在何种显示比例和容器尺寸下，标注位置始终准确。

**多框叠加管理**：
- 同一个标签可以在同一张图片上绘制多个框；
- 支持多种标签的框在同一张图片上共存；
- 已保存的框在切换回该图片时自动加载显示。

#### 4.3.5 标注数据导出

**按模式导出**：
- `mode=qa`：仅导出问答标注数据和对应图片；
- `mode=box`：仅导出框选标注数据和对应图片；
- `mode=all`：同时导出问答和框选标注及图片。

**导出包结构**：
```
<项目名>_<时间戳>.zip
└── <项目名>/
    ├── 标注结果_qa.jsonl         ← 问答标注记录（按模式）
    ├── 标注结果_boxes.jsonl      ← 框选标注记录（按模式）
    ├── images/                   ← 已标注的图片文件
    │   └── <图片文件名>
    └── README.txt                ← 导出说明
```

### 4.4 数据导出模块

#### 4.4.1 文本标注导出

| 格式 | API端点 | 说明 |

```json
      }],
```

**CSV/TSV格式转义处理**：
- 文本片段中的Tab符替换为空格，换行符替换为空格；

图像标注模块通过`/api/export-zip?mode=qa|box|all`端点导出ZIP压缩包，包含JSONL标注文件和已标注图片。详细结构见4.3.5节。

```json
    "box_jsonl_path": "projects/犬种识别项目/标注结果_boxes.jsonl",
    "labels": ["dog", "cat", "bird"],
    "last_image": "dog_001.png"
  }
]
```

### 5.3 数据完整性约束

1. **实体引用完整性**：关系标注中的`from_ann_id`和`to_ann_id`必须在同一文档的标注中存在；
2. **项目级联删除**：删除项目时，级联删除其所有文档、标注和关系记录；
3. **标注级联删除**：删除标注时，级联删除关联该标注的所有关系记录；
4. **标签合法性校验**：新增标注时，标签必须在项目配置的标签列表中；
5. **区间合法性校验**：标注的起止位置必须在文本长度范围内，且`start < end`；
6. **区间重叠控制**：当项目配置不允许重叠时，新标注不能与已有标注重叠（同一文档内）；
7. **关系重复控制**：同文档内，相同源、目标和类型的关系不允许重复；
8. **项目名称唯一性**：文本标注和图像标注中，项目名称均在各自域内唯一。

### 7.1 设计系统（Design System）

文本标注前端定义了一套完整的设计令牌（Design Tokens）体系，通过CSS自定义属性（CSS Variables）实现：

- 主色（Primary）：`#1E40AF` → `#3B82F6`，蓝色系，用于品牌标识、主按钮、激活状态；

### 7.5 性能优化设计

1. **字符级渲染的Rect缓存**：通过`useLayoutEffect`在每次文本或标注变化时重新度量所有字符的屏幕位置，避免滚动或缩放时的偏移误差。

2. **ResizeObserver替代**：使用`window.resize`事件监听窗口尺寸变化，触发重新度量。

3. **键盘事件Ref模式**：键盘事件监听器通过`useRef`持有最新状态引用，使用`useEffect([], [])`只绑定一次事件监听器，避免每次渲染都重新绑定（严重性能问题）。

4. **图片列表前端缓存**：图像标注前端在内存中维护已标注图片集合（`labeledSet`），避免每次切换图片都请求后端。

5. **Vite按需构建**：利用Vite的ES模块原生支持和热模块替换（HMR），在开发阶段实现极速的代码更新。

## 8. 安全设计

### 8.1 认证与授权

**JWT令牌机制**：
- 签名算法：HMAC-SHA256（HS256）；
- 有效期：7天；
- Payload包含：`user_id`、`username`、`exp`（过期时间）、`iat`（签发时间）；
- 令牌存储在`sessionStorage`中，关闭浏览器标签页后自动清除。

**认证中间件防护**：
- 严格拦截`/api/*`路径，白名单机制排除认证接口和健康检查；
- Token缺失、格式错误、无效或过期均返回401 Unauthorized；
- Token验证失败时返回统一错误格式，不泄露内部实现细节（如密钥信息）。

### 8.2 输入校验

**后端校验**：
- 所有API请求体通过Pydantic模型进行类型校验（图像标注子系统）；
- 标注区间边界检查：`start >= 0`、`end > start`、`end <= len(text)`；
- 标签合法性检查：标注的标签必须在项目配置的标签列表中；
- 关系类型合法性检查：关系类型必须在项目配置的关系类型列表中；
- 项目名称非空校验。

**前端校验**：
- 助手回答不能为空（问答标注保存时检查）；
- 框选标注至少需要选择一个标签；
- 拖拽绘制的框最小尺寸不低于3像素（防止误触）。

### 8.3 数据安全

**文件路径安全**：
- 项目名称在创建文件系统目录前进行安全字符过滤，仅保留字母数字、空格、连字符和下划线；
- 所有文件操作基于项目根目录下的相对路径，防止路径穿越攻击。

**日志安全**：
- 认证成功日志记录用户ID和用户名，便于审计追踪；
- 认证失败日志记录失败原因但不暴露敏感信息（仅记录"用户名或密码错误"而非具体的用户名不存在或密码不匹配）。

**敏感信息保护**：
- JWT密钥自动生成并持久化，不硬编码在代码中；
- 支持通过环境变量注入密钥，避免配置文件泄露风险；
- 用户密码（当前阶段）以明文存储在Excel中，建议未来版本迁移至哈希存储。

### 8.4 CORS策略

- 当前配置为`allow_origins=["*"]`，允许任意来源跨域访问，适用于开发和内网部署场景；
- 生产环境中应替换为具体的可信域名列表；
- 生产环境中应设置`allow_credentials=True`配合具体origin（不允许`*`与credentials共存）。

- 前端Vite dev server监听5173端口，通过proxy配置将`/api`和`/minimind`请求代转到后端8000端口；
- 后端Uvicorn监听8000端口，启用`--reload`热重载；
- 两个进程通过`start.bat`脚本分别在独立的终端窗口中启动。

#### 9.1.2 生产部署模式（Docker）

```
┌─────────────────────────────────────────┐
│            Docker Container             │
│  ┌───────────────────────────────────┐  │
│  │     Uvicorn (3002)                │  │
│  │     FastAPI Server                │  │
│  │     ├─ 文本标注器                  │  │
│  │     ├─ 图像标注器                  │  │
│  │     └─ 前端静态文件 (SPA)          │  │
│  └───────────────────────────────────┘  │
│  ┌───────────────────────────────────┐  │
│  │     SQLite + 文件系统              │  │
│  │     (通过 Volume 挂载持久化)        │  │
│  └───────────────────────────────────┘  │
└─────────────────────────────────────────┘
```

- 前端构建产物（`dist/`）在生产模式下由FastAPI直接托管，单进程服务，架构简单；
- 用户通过浏览器直接访问3002端口即可获得完整功能。

#### 9.1.3 离线部署模式

```
┌──────────────────────────────────────────┐
│       离线服务器 (无互联网访问)             │
│  ┌────────────────────────────────────┐  │
│  │  Docker (label-fast:latest 镜像)    │  │
│  │  ├─ 离线Vue.js (本地静态文件)        │  │
│  │  ├─ 离线Tailwind CSS (本地静态文件)   │  │
│  │  ├─ 离线Python依赖 (镜像内置)         │  │
│  │  └─ 离线npm包 (镜像内置)              │  │
│  └────────────────────────────────────┘  │
└──────────────────────────────────────────┘
```

- Dockerfile中内置了`curl`下载Vue.js和Tailwind CDN资源到本地`static/`目录的步骤；
- 图像标注前端引用本地静态文件（`./static/vue.global.js`、`./static/tailwind.js`），不依赖CDN；
- 所有Python依赖通过pip安装到镜像中。

### 9.2 Docker多阶段构建

**阶段一：前端构建（frontend-builder）**
- 基础镜像：`node:20-alpine`（轻量级Node.js运行环境）；
- 利用Docker层缓存：先复制`package.json`和`package-lock.json`，执行`npm ci`安装依赖；
- 再复制前端源码，执行`npm run build`生成生产构建产物。

**阶段二：运行时镜像**
- 基础镜像：`python:3.10-slim`；
- 安装系统依赖：`libgomp1`（onnxruntime依赖）、`curl`（下载离线资源）；
- 安装Python依赖：`fastapi`、`uvicorn`、`SQLAlchemy`、`pydantic`、`pyjwt`、`openpyxl`等；
- 复制后端代码和图像标注器额外依赖；
- 下载离线前端CDN资源；
- 创建种子数据备份（首次部署时volume为空则自动恢复）；
- 从前端构建阶段复制构建产物；
- 配置`ENTRYPOINT`为`docker-entrypoint.sh`启动脚本。

### 9.3 docker-compose编排

`docker-compose.offline.yml`定义了离线部署的服务编排：

- **容器名称**：`label-fast`；
- **端口映射**：`3002:3002`；
- **数据卷挂载**：
  - `./backend/文本标注器/projects` → 文本标注项目目录；
  - `./backend/文本标注器/storage` → SQLite数据库目录；
  - `./backend/图像标注器/projects` → 图像标注项目目录；
  - `./backend/图像标注器/projects.json` → 图像标注项目索引；
  - `./backend/users.xlsx` → 用户账号文件；
- **重启策略**：`unless-stopped`（除非手动停止）；
- **环境变量**：设置`OPENBLAS_NUM_THREADS=1`、`GOTO_NUM_THREADS=1`、`OMP_NUM_THREADS=1`，限制数学库线程数以适配容器环境。

### 9.4 容器启动流程

`docker-entrypoint.sh`脚本在容器启动时执行以下检查：

1. **文本标注数据库检查**：检查SQLite数据库文件是否存在且大小正常（≥1024字节），如果不存在或为空，从种子数据恢复；
2. **文本标注项目数据检查**：检查`projects/`目录是否为空，如果为空从种子数据恢复；
3. **图像标注项目数据检查**：检查图像标注项目目录和`projects.json`索引，如果不存在从种子数据恢复；
4. **启动服务**：通过`exec "$@"`启动uvicorn服务。

### 9.5 前端环境配置

根据CLAUDE.md中的"前端网络架构规则"，前端配置必须遵守以下原则：

1. **`API_BASE`为空字符串**：所有API请求走相对路径（如`/api/projects`），不硬编码主机名或端口；
2. **Vite配置代理**：开发模式下，`/api`和`/minimind`路径的请求代理到后端（`http://127.0.0.1:${BACKEND_PORT}`）；
3. **`server.host: '0.0.0.0'`**：确保局域网内其他设备可访问前端开发服务器。

### 12.2 关键设计决策记录

| 编号 | 决策 | 原因 | 影响 |
|------|------|------|------|
| AD-001 | SQLite作为数据库 | 零配置部署，无需独立数据库服务；单机场景满足需求 | 不适合高并发多写场景；未来可迁移到PostgreSQL |
| AD-002 | Excel文件管理用户 | 简化部署配置，管理员可直接编辑；适合小团队 | 密码明文存储；未来应迁移到数据库+哈希 |
| AD-003 | 文本+图像双子系统共存 | 一套系统覆盖NLP和CV标注需求，统一项目管理和部署 | 前端使用不同技术栈；API路由需挂载协调 |
| AD-004 | 字符级文本渲染 | 实现精确的像素级标注框定位；支持任意缩放 | 长文本性能需关注；Rect度量成本较高 |
| AD-005 | JSONL双写策略 | 数据库保证事务性和查询能力；JSONL保证数据可溯源性 | 需维护两类存储的一致性 |
| AD-006 | 图像标注子系统独立FastAPI应用 | 可独立开发和测试；通过mount集成 | 需注意路径前缀和静态资源引用 |
| AD-007 | JWT无状态认证 | 无需服务端Session存储；适合容器化水平扩展 | Token撤销困难；未来可引入黑名单机制 |
| AD-008 | 图像标注前端离线静态资源 | 确保内网/无互联网环境可用；不依赖CDN | 需在构建时下载CDN资源；资源版本更新需重新构建镜像 |
| AD-009 | 前端SPA由后端托管（生产模式） | 单进程部署，无需Nginx；减少运维复杂度 | 静态资源服务性能不如Nginx；未来可分离部署 |

### 12.3 未来演进方向

1. **数据库升级**：从SQLite迁移到PostgreSQL，支持更高并发和更强大的查询能力；
2. **实时协作**：引入WebSocket实现多人实时标注协作；
3. **标注质量审核**：增加审核流程（标注→审核→通过/驳回），支持标注员、审核员角色分离；
4. **自动标注辅助**：集成预训练模型提供自动标注建议，降低人工标注工作量；
5. **标注统计分析**：增加标注进度统计、标注员工作量统计、标注一致性分析等报表功能；
6. **更多标注类型**：支持图像分割标注（多边形/画笔）、视频标注、音频标注等；
7. **API文档增强**：为所有API端点补充完整的请求/响应示例和参数说明；
8. **前端组件库统一**：将文本标注的React和图像标注的Vue.js统一为同一技术栈；
9. **国际化**：支持多语言界面切换。
